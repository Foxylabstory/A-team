# Пробный загрузчик Instagram на Render

На Render размещается только папка `A-Team/server/instagram-loader`. Сайт клуба,
SQLite, заявки, резервные копии и ключи Telegram остаются на российском сервере.
GitHub Actions и Apify для загрузчика не используются.

Render Free подходит для проверки, но сам Render не рекомендует его для production.
После 15 минут простоя он засыпает; запуск по запросу занимает около минуты.
Его локальные файлы теряются после остановки/перезапуска. Это допустимо для временного
кеша загрузчика: постоянные новости и фотографии уже сохранены на сервере клуба.
Доступ к Instagram нужно проверять именно с выбранного хостинга.

## Настройка

1. Войти в [Render](https://dashboard.render.com/) и выбрать **New → Web Service**.
2. Подключить репозиторий, в который опубликована актуальная папка загрузчика.
   Одного локального изменения файлов недостаточно; публикация выполняется отдельно.
3. Выбрать **Language: Docker**, папку сервиса **A-Team/server/instagram-loader**,
   Dockerfile **./Dockerfile**, контекст сборки **.**, тариф **Free**.
4. Указать Health Check Path **/health**.
5. В **Environment** задать:

| Переменная | Значение |
| --- | --- |
| `NEWS_LOADER_TOKEN` | Новый случайный общий секрет, минимум 32 символа |
| `IG_SOURCE` | `instaloader` |
| `IG_NEWS_ACCOUNT` | `antipov__team` |
| `IG_NEWS_HASHTAG` | `новости` |
| `IG_SCAN_LIMIT` | `100` |

Dockerfile уже задаёт правильный Python и `HOST=0.0.0.0`. Порт Render передаёт через
`PORT`. Не включайте APIFY_TOKEN, ключи Telegram, базу или `.env` сайта в настройки
этого сервиса. В Dockerfile нет аргументов сборки с секретами.

6. После успешного запуска скопировать выданный HTTPS-адрес сервиса и добавить `/news`.
   На сервере клуба в закрытом `.env` задать:

```dotenv
IG_NEWS_FEED_URL=https://имя-сервиса.onrender.com/news
IG_NEWS_FEED_TOKEN=тот_же_секрет_что_NEWS_LOADER_TOKEN
IG_NEWS_ACCOUNT=antipov__team
IG_NEWS_HASHTAG=новости
NEWS_AUTO_UPDATE=true
NEWS_ASYNC_IMPORT=true
```

7. Перезапустить сайт. В админке **Новости → Загрузить из Instagram** запустится сбор
   в фоне. Сайт ожидает до 20 минут, сами обращения ограничены по времени. Посетителям
   в это время показывается предыдущая лента. В логе Render не выводятся тексты
   публикаций, cookies или ключи.

## Если Instagram потребует вход

Сначала используется анонимный доступ; регистрацию разработчика Meta проходить не надо.
Если он перестал работать, создайте JSON-сессию командой из README. В Render откройте
**Environment → Secret Files → Add Secret File**, имя `instagram-session.json`, содержимое
— полученный закрытый файл. Задайте `IG_SESSION_FILE=/etc/secrets/instagram-session.json`.
Сессия даёт доступ к аккаунту Instagram; передавайте её только доверенному хостингу.
Публиковать её в репозитории или чате нельзя. Docker-образ сессий не содержит.

## Постоянная работа

Для постоянной работы выберите доступный сервер вне РФ с Node.js и Python либо
подходящий постоянный тариф хостинга. Instaloader бесплатен; стоимость размещения
зависит от провайдера. Сбой источника не удаляет сохранённые на сайте новости.

Официальные источники: [лимиты Free](https://render.com/docs/free),
[Docker](https://render.com/docs/docker),
[переменные и секретные файлы](https://render.com/docs/configure-environment-variables).
