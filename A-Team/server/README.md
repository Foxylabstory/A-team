# ANTIPOV TEAM — сервер сайта и заявки

Node.js 24.13+ (рекомендуется актуальная Node.js 24 LTS), Express 4, встроенная SQLite.
Сайт, база и закрытый кабинет работают на одном сервере. Для публикации выберите сервер
и диски в РФ, включая резервные копии. Статический хостинг без Node.js для этой версии не подходит.

## Первый запуск

Из папки `A-Team/server`:

```powershell
Copy-Item .env.example .env
npm ci
npm run db:init
npm run admin:password
npm start
```

Сайт: `http://127.0.0.1:3000/`. Кабинет: `http://127.0.0.1:3000/admin/`.
Команда `admin:password` попросит дважды ввести новый пароль. Ввод скрыт.
Пароля по умолчанию нет. При незаданном пароле вход закрыт.
База создаётся также при первом запуске сервера; в репозитории нет паролей или данных клиентов.

## Как администратор видит заявки

Откройте `/admin/` на домене клуба и введите пароль. Это одна учётная запись администратора.
В кабинете доступны имя, телефон (с кнопкой звонка), дата по Москве, сохранённое согласие,
статус заявки и состояние уведомления. Статусы: «Новая», «Связались», «Записан», «Закрыта».
Есть фильтр, страницы по 25 заявок, обновление вручную и раз в минуту в активной вкладке,
удаление с подтверждением, история действий и смена пароля.
Раздел «Новости» использует тот же защищённый сеанс. Управление перенесено в кабинет.

## Пароль раскрыт или забыт

Если доступ к кабинету есть: вкладка «Сменить пароль», текущий пароль и новый пароль дважды.
Новый пароль — не менее 14 символов и не более 256 байт UTF-8. После смены ВСЕ сеансы
на всех устройствах отзываются, включая текущий. Старый пароль больше не подходит.

Для восстановления через браузер заранее создайте код в разделе «Сменить пароль» →
«Код восстановления». Сохраните его в менеджере паролей под названием
**Antipov Team — код восстановления** и добавьте адрес `https://antipov.team/admin/`.
В репозитории храните только эту памятку. Кабинет показывает код один раз,
а сервер сохраняет его хеш.

При потере пароля нажмите «Забыли пароль?» на странице входа и введите сохранённый
код и новый пароль. Сброс завершит все сеансы. Код действует до первого использования,
замены кода или смены пароля. После восстановления создайте новый код.

Если код недоступен, зайдите на сервер через SSH, перейдите в каталог приложения
и выполните команду восстановления:

```bash
npm run admin:password
```

Для восстановления старый пароль не нужен: право сброса даёт доступ к серверу.
Команда работает и при запущенном сайте, отзывает все сеансы и снимает временную
блокировку входа. Не передавайте новый пароль в аргументах команды, чате или `.env`.
Если раскрыт также SSH-доступ, сначала восстановите контроль над сервером и проверьте его.
При восстановлении базы из старой резервной копии выполните эту команду повторно,
чтобы не вернуть старый пароль и сеансы.

Хранится только scrypt-хеш с индивидуальной солью. Сеанс — случайный токен в
HttpOnly/SameSite=Strict cookie, а в базе хранится его SHA-256-хеш. Срок сеанса — 8 часов.
На production cookie имеет Secure; нужен HTTPS. Токен и пароль не сохраняются в
localStorage/sessionStorage. Старый ADMIN_TOKEN не даёт доступа ни к заявкам, ни к новостям.
Вход ограничен по частоте; ограничения переживают перезапуск сервера.
Изменения защищены CSRF-токеном и проверкой Origin. IP не доверяется из произвольного
X-Forwarded-For: доверие прокси включается отдельно.

## Как сохраняется заявка и отправляется уведомление

`POST /api/lead` проверяет имя, телефон, согласие и версию согласия. Заявка и задача
уведомления записываются одной транзакцией в SQLite. Только после успешной записи
посетитель видит подтверждение. База: `data/club.sqlite`, вне `public/`.
Хранятся имя, телефон, даты, статус, текст и версия согласия. В заявке не хранятся дата рождения,
данные ребёнка, исходный IP и устройство посетителя. Для ограничения спама используется краткоживущий
HMAC от IP; в журнале действий нет имён, телефонов, паролей или текстов запросов.

Для Telegram задайте в `.env`:

```dotenv
TG_BOT_TOKEN=токен_вашего_бота
TG_CHAT_ID=идентификатор_группы
SITE_URL=https://ваш-домен.ru
```

Бот должен иметь право писать в выбранную группу. В сообщении только общий текст
«Поступила новая заявка» и кнопка на `/admin/`. Нет имени, телефона, номера заявки,
времени согласия или иных полей клиента. Контакты видны после входа на сайте.
Бот проверяет очередь каждые 15 секунд. При ошибке — до 6 попыток с увеличением интервала.
После исчерпания попыток в кабинете появляется кнопка повтора. Если Telegram не настроен,
заявки продолжают сохраняться, задачи ждут настройки. После изменения `.env` перезапустите сервер.
Уведомления доставляются как минимум один раз: при аварии между ответом Telegram и
фиксацией результата в базе возможен повтор одного общего уведомления.
Доступность Telegram API проверяется с выбранного хостинга; сбой не влияет на сохранение заявок.

## Публикация на сервере в РФ

[Автоматическая выкладка из `master` через GitHub Actions](deploy/README.md).

В `.env` установите `NODE_ENV=production`, `SITE_URL=https://реальный-домен.ru`.
Сервер по умолчанию слушает только `127.0.0.1:3000`. Перед ним настройте nginx с HTTPS.
Если nginx находится на той же машине, установите `TRUST_PROXY=loopback`.
Проксируйте сайт И `/api/` на Node.js, а также перезаписывайте входящие заголовки:

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Real-IP $remote_addr;
}
```

Не публикуйте папку проекта целиком как каталог nginx. Публичная папка — только `public/`.
`.env`, `data/`, `backups/`, служебные файлы и тесты не должны отдаваться веб-сервером.
Для данных нужен постоянный локальный диск: не временный контейнерный слой и не сетевой
файл SQLite. Выдайте доступ к папкам данных только учётной записи приложения/владельцу.
При нескольких экземплярах сервера или большом числе одновременных записей потребуется
другая конфигурация базы и очереди; текущий вариант рассчитан на один сервер клуба.

## Резервные копии и срок хранения

```bash
npm run db:backup
```

Создаёт согласованный снимок SQLite в `backups/` через SQLite Backup API и папку `.sqlite.media` с фотографиями новостей из этого снимка. При восстановлении верните снимок как `data/club.sqlite`, а фотографии — в `data/news-images/`. Рекомендуется
ежедневный запуск планировщиком и отдельное защищённое хранилище в РФ. Автоматический
запуск резервирования и внешнее хранилище эта команда не настраивает.
Не копируйте работающую базу как один файл без WAL: используйте команду выше.
Копия содержит персональные данные и хеши доступа — защищайте и её.

`LEAD_RETENTION_DAYS=90` — исходное рабочее значение, НЕ установленный законом срок.
Оператор должен выбрать срок под цель обработки и отразить его в своих документах.
При запуске и раз в час старые заявки удаляются из рабочей базы, связанные задачи
уведомлений удаляются вместе с ними. Сеансы и истёкшие ограничения тоже очищаются.
Архивные копии автоматически не удаляются: для них отдельно настройте срок хранения
и удаление. Удаление отдельной заявки в кабинете не редактирует уже созданные копии.

## Содержимое проекта

- `server.js` — запуск и остановка.
- `lib/app.js` — HTTP API, доступ, валидация, закрытые операции.
- `lib/database.js` — схема SQLite, транзакции, версия согласия, сроки хранения.
- `lib/auth.js` — пароль и сеансы.
- `lib/notifications.js` — устойчивая очередь общих уведомлений.
- `lib/news.js` — управление новостями в SQLite, изображения, ручной и ежедневный импорт Instagram.
- `public/admin/` — кабинет администратора, без внешних скриптов и шрифтов.
- `public/index.html` — лендинг с рабочей формой. Корневой `index.html` и `docs/index.html`
  также обновлены для обращения к API. При самостоятельной статической публикации эти
  копии требуют серверной части на том же домене.
- `scripts/manage.js` — создание базы, пароль, резервная копия.
- `test/app.test.js` — проверки с временными базами и подменённым Telegram.

Фотографии и реквизиты-заглушки в остальных разделах лендинга
требуют заполнения перед публикацией. Техническая реализация не заменяет основание
обработки данных, документы оператора и необходимые организационные меры.

## Проверки

```bash
npm test
```

Проверяются сохранение заявки и согласия, защита базы от скачивания, отсутствие контактов
в уведомлении, повтор отправки, вход и ограничения, CSRF, смена и восстановление пароля,
отзыв сеансов, удаление, срок хранения и интеграция всех трёх копий лендинга.
Тесты не обращаются к реальным Telegram/Instagram и не создают реальные заявки.

Дополнительно: `npm run test:ui` проверяет форму и кабинет в установленном Edge/Chrome/Chromium
с временной базой и тестовым паролем. При необходимости задайте `BROWSER_EXECUTABLE`.
Снимки компьютера и узкого экрана сохраняются в `screenshots/`; в них только тестовые данные.

## Управление новостями

В `/admin/` → «Новости» доступны создание и редактирование ручной новости, загрузка
фотографии с компьютера (JPEG/PNG/WebP до 2 МБ), удаление публикаций, явный импорт
из Instagram и восстановление скрытых записей. Заголовок — до 120 символов, текст —
до 2000 символов. На основной странице показываются три последние видимые новости
обоих источников, отсортированных по дате публикации. Изменения видны при обновлении сайта.

Ручная новость удаляется из рабочей базы. Публикация Instagram при удалении с сайта
попадает в «Скрытые»: её идентификатор сохраняется, поэтому следующий импорт её
не вернёт. В самом Instagram ничего не удаляется. Для возврата используйте «Вернуть
на сайт». Повторный импорт обновляет существующие записи без дубликатов. Редактирование
текста доступно для ручных новостей; Instagram остаётся источником своего текста.
Удаление тега в Instagram само по себе не удаляет уже импортированную новость с сайта.

После подключения источника сервер проверяет Instagram раз в сутки. Можно запустить
импорт вручную по кнопке администратора. Посетители сайта не запускают внешние запросы.
`NEWS_AUTO_UPDATE=false` отключает расписание, сохраняя ручную загрузку. Успешный импорт
откладывает следующую автоматическую проверку на сутки; после ошибки повтор выполняется
не раньше чем через час. Даты и состояние ошибки сохраняются в SQLite и переживают
перезапуск. В админке видны аккаунт, последняя успешная загрузка, следующая проверка и
ошибка доступа. Одновременно выполняется только один импорт.

Импортируются до трёх последних публикаций аккаунта с точным #новости, на сайте
показываются три самые свежие видимые новости. Тег настраивается через
`IG_NEWS_HASHTAG`. Для клуба задайте `IG_NEWS_ACCOUNT=antipov__team` на обеих сторонах:
загрузчик сверяет имя с официальным API и не отдаёт публикации другого аккаунта.
Для российского сервера используйте отдельный загрузчик по инструкции
[instagram-loader/README.md](instagram-loader/README.md). Если API и фото Meta доступны
с самого сервера, возможно прямое подключение через `IG_USER_ID` и `IG_ACCESS_TOKEN`.
Без настроек кнопка отключена; при сетевой ошибке сохранённые новости не пропадают.
Instagram-импорт не использует Apify; его ключ нужен только для отдельного механизма отзывов 2ГИС.
Основной вариант отдельного загрузчика — `IG_SOURCE=instaloader`, без регистрации
разработчика Meta. Для него задайте на сайте `NEWS_ASYNC_IMPORT=true`: загрузка
выполняется в фоне и может продолжаться несколько минут, даже если закрыть админку.
Загрузчик возвращает `202` до готовности подборки; сайт ожидает результат до 20 минут.
В админке видны ход загрузки, ошибки доступа и результат. Обычный вход в Instagram
нужен только если источник потребует сессию. Пробное размещение описано в
[инструкциях Railway](instagram-loader/DEPLOY-RAILWAY.md) и
[Render](instagram-loader/DEPLOY-RENDER.md); рабочий доступ с хостинга
проверяется отдельно, а сайт и база остаются в РФ.

Для локального просмотра два процесса могут работать на одном компьютере: сайт на
`127.0.0.1:3000`, загрузчик на `127.0.0.1:3100`. Только в development допускается
`IG_NEWS_FEED_URL=http://127.0.0.1:3100/news`; в production нужен HTTPS-адрес.
Чтобы обновления выполнялись, должны работать оба процесса. Сохранённые новости и
фотографии остаются в базе и на диске после остановки загрузчика.
Если Instagram доступен с выбранного российского хостинга, загрузчик можно разместить
на том же сервере. Если доступ закрыт, его размещают отдельно; предварительная
проверка с конкретного хостинга обязательна для выбора схемы.

Тексты и фотографии импортированных новостей сохраняются на сервере клуба. Браузер
посетителя не обращается к Meta для отображения новых импортов. Токены внешнего источника
не передаются в браузер. Бэкап теперь включает фото новостей; не удаляйте папку `.media`
при переносе снимка базы. Срок хранения заявок не применяется к новостям. Неиспользуемые
загруженные фото старше суток очищаются при следующей загрузке нового изображения.

В режиме Instaloader скачиваются MP4 только для трёх показываемых новостей, до 100 МиБ
каждый. Видеофайлы лежат в закрытой папке `data/news-videos/` и выдаются через сайт
с поддержкой Range/перемотки. Плеер запускается по действию посетителя, без автозапуска.
Для карусели берётся первый ролик. При ошибке загрузки остаются текст и обложка,
подробность видна в админке. Скрытие, удаление или вытеснение новости из тройки
запускает удаление ненужного видео; занятые файлы повторно очищаются раз в минуту.
Текст, фотографии и настройки скрытия при этом остаются. Видео — восстанавливаемый кеш,
в резервную копию не включается; после восстановления базы доступные ролики снова
скачаются при импорте. Официальный API в текущей реализации сохраняет только обложки.

При первом запуске старый `data/news.json` переносится в SQLite один раз с сохранением
существующих идентификаторов. Исходный файл остаётся для восстановления; новые записи
в него больше не пишутся. Ручные данные и скрытые публикации переживают перезапуск.

## Статическая версия для GitHub Pages

Корневой `index.html` и папка `docs/` содержат статическую версию для показа сайта.
В настройках GitHub Pages можно выбрать ветку `master` и папку `/docs` (или `/`).
Ссылки на изображения относительные: страница работает и по адресу `/A-team/`.
В статической версии запись ведёт на телефон клуба; форма с персональными данными и
ссылка на закрытую админку не отображаются. Серверная версия в `public/` сохраняет
рабочую форму, базу заявок и управление новостями.

Для статических новостей используется `docs/assets/news.json` (и его копия `assets/news.json`).
Это публичные данные с форматом `/api/news`; базы заявок, пароли и `.env` в Pages не попадают.

## Подключение 2ГИС

Источник — `zen-studio/2gis-reviews-scraper` на Apify, карточка клуба
`https://2gis.ru/nabchelny/firm/70000001096882624`. Ключ официального API 2ГИС не нужен.
Сервер использует `APIFY_TOKEN` из локального `.env`; `REVIEWS_AUTO_UPDATE=false`
отключает автоматический сбор, сохраняя показ уже полученных данных.

На странице показываются общий рейтинг карточки, количество текстовых отзывов и
три последних опубликованных отзыва с оценкой 5. Сортировка — по дате создания:
закрепление, подтверждённые посещения и позднее редактирование не поднимают старый
отзыв выше новых. Скрытые и лишённые оценки отзывы исключаются. Общий рейтинг
берётся из данных карточки и не вычисляется по выбранным трём пятёркам.
Число текстовых отзывов не является числом всех оценок без текста.

`GET /api/reviews` отдаёт только публичные поля и три отзыва. Персональные данные
из заявок не передаются в Apify. Сбор выполняется на стороне зарубежной платформы
Apify; имя автора и текст отзыва поступают оттуда. Ключ и полный профиль автора
не включаются в публичный JSON. Если прямой ссылки на отзыв нет, используется
ссылка на вкладку отзывов клуба в 2ГИС.

Пока Node-сервер работает, он раз в час проверяет необходимость обновления.
Фактический запуск Apify происходит не чаще одного раза за 24 часа. Последняя
попытка сохраняется до запуска в `data/reviews-update-state.json`, поэтому
перезапуск сервера и ошибки источника не вызывают повторных списаний в тот же день.
Кэш `data/reviews-cache.json` сохраняется между перезапусками. При сетевой ошибке,
неполной выдаче или неверных данных на странице остаются предыдущие отзывы.
Посещение сайта никогда не запускает Apify.

Автоматический сбор разрешён только на плане Free, при наличии не менее $0,12
бесплатного остатка. Предел одного запуска — $0,12, память — 512 МБ, тайм-аут —
180 секунд, до 100 отзывов. Повторный POST при потере ответа не выполняется.
Если отзывов станет больше 100, неполная выборка не публикуется: нужно пересмотреть
лимит и бюджет в `lib/apify-reviews.js`. В проверенном запуске 46 отзывов стоили
$0,053, включая $0,007 за запуск; это наблюдение, тариф сервиса может измениться.

Ручное обновление кэша:

```powershell
npm run reviews:refresh
```

Запущенный сайт подхватывает новый файл кэша при следующем запросе. Для локального
экспорта публичного снимка в `public/assets/`, `docs/assets/` и корневую `assets/`:

```powershell
npm run reviews:refresh -- --export-static
```

Эти копии используются для показа статической версии. GitHub Actions в обновлении
отзывов не участвует; продуктовая схема работает на сервере клуба.
